# Contributing Guidelines
1. Never push directly to main.
2. Every feature gets its own branch.
3. Every branch must build successfully.
4. Every API change must update documentation.
5. Every database change requires a migration.
6. Never commit .env files or secrets.
7. Never duplicate shared types.
8. Frontend and backend communicate through documented APIs.
9. Every completed module must include tests.
10. Before merging, test against develop.
11. Breaking changes must be announced to the team.
12. Update documentation while developing, not at the end.
13. Don't rewrite another member's module without discussion.
14. Major architecture changes require team approval.
15. Merge only after review + CI passes.
